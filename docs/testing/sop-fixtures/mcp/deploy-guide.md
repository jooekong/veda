# Veda 服务部署指南(测试语料)

> 哨兵:SOP_MD_SENTINEL_71 —— 本文件是 MCP 手测语料,内容为虚构示例。

## 发布前检查

发布任何版本之前,值班工程师必须确认三件事:集成测试基线全部通过、变更日志已经更新、回滚用的备份二进制仍然保留在部署目录。缺任何一项都不允许进入发布流程。

## 灰度顺序

部署严格遵循三段灰度:先发 **金丝雀节点**,观察十五分钟无异常后发 **全量测试环境**,最后才允许上 **生产环境**。生产发布必须选择业务低峰时段,并且发布人和复核人不能是同一个人。

### 金丝雀观察指标

金丝雀阶段重点盯三个指标:错误率不高于百分之一、p99 延迟不高于两百毫秒、内存占用相比发布前不上涨超过一成。任何一项越线立即回滚。

## 回滚流程

回滚采用备份二进制原子替换的方式:先把备份文件重命名回主路径,再重启服务进程,整个过程控制在三十秒内。回滚之后必须在群里同步原因,并在四十八小时内补一份事故复盘文档。

## 常见问题

- 配置文件改动不需要重新编译,重启服务即可生效。
- 数据库结构变更必须走独立的迁移评审,不允许夹带在普通发布里。
- 发布窗口冻结期为每年大促前一周,期间只允许紧急修复上线。
