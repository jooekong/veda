## 一、必须修 before 全员开放（去重后 5 条）

> 工作流报了 10 个 blocker，去重后是 5 个真问题：A-1 被 4 个维度各报一次、apps.rs 被报 3 次、SQL 逃逸是 2 条同根。每条已独立判定，并标注 agent 报错/夸大处。

### 🔴 B1. `/v1/sql` 可写宿主机任意文件（read_only 也挡不住）—— **新发现，作者已读码亲核**

- **位置**：`crates/veda-sql/src/engine.rs:55`（裸 `SessionContext::new()`，默认 DDL/DML/statements 全开）+ `:115`（`ctx.sql(sql)` 不带 `SQLOptions`）。`read_only` 参数只流进 `FsUdfContext`（`engine.rs:75`），**不进 DataFusion planner**。入口 `crates/veda-server/src/routes/sql.rs:17-25`（`AuthWorkspace`，任意 fs `wk_` 可达，含只读 key）。
- **利用**：`POST /v1/sql {"sql":"COPY (SELECT 1 as x) TO '/root/.ssh/authorized_keys'"}` → 以 server uid 写/覆盖宿主机任意文件。agent 实测 `COPY (SELECT 'pwned') TO '/tmp/...'` 覆盖了既有宿主机文件成功；作者读码确认路径与 `read_only` 不参与门控。
- **影响**：前序 review 记录 **prod 以 root 跑** → 覆盖 `authorized_keys` / `/etc/cron.d/*` / systemd unit = 直接 RCE。**范围澄清**：这是宿主机 FS 逃逸，**不是跨租户**（SQL 跨租户隔离 agent 已逐表证实是紧的）。
- **修复（agent 已编译验证、作者确认无副作用）**：`engine.rs:115` 改为
  ```rust
  ctx.sql_with_options(sql, SQLOptions::new()
      .with_allow_ddl(false).with_allow_dml(false).with_allow_statements(false))
  ```
  挡掉 COPY / CREATE EXTERNAL TABLE / SET；`SELECT` + `veda_*` 写 UDF（走 Projection + 自身 read_only 闸）不受影响。**6 行、零副作用、全场最高 ROI。** 修完补回归测试断言 `COPY ... TO` 返回 Err。

### 🔴 B2. `/v1/sql` 无内存/超时/行数上限

- **位置**：`engine.rs:55`（`RuntimeEnv::default()` = `UnboundedMemoryPool`）；`engine.rs:119` `df.collect()` 全量物化；`main.rs:328-331` 中间件栈无 `TimeoutLayer`；`routes/sql.rs` 无 `DefaultBodyLimit`。
- **利用**：`SELECT a.value FROM generate_series(1,100000) a, generate_series(1,100000) b ORDER BY a.value` = 1e10 行笛卡尔积 + 无界排序，无 memory pool 中止、无超时切断 → 一个员工 OOM/打满整个单节点，全员遭殃。
- **修复**：`engine.rs:55` 用 `RuntimeEnvBuilder::new().with_memory_pool(Arc::new(GreedyMemoryPool::new(256*1024*1024)))`；`df.collect()` 包 `tokio::time::timeout(30s)`。

## 三、边缘/可延后（符合"不过度"偏好，建议先不动）

- **RUSTSEC 3 条**：`rustls-webpki 0.103.12`（RUSTSEC-2026-0104，**值得 `cargo update -p rustls-webpki`**）、`rsa 0.9.10`（无 fix）、`quinn-proto`（未编译）。
