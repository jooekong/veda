## 三、明确**不修**（已考虑并丢弃 / 已证伪，尊重不过度偏好）

- **全局 `ConcurrencyLimit`/`LoadShed`** —— MySQL 池（`max_connections=50`/`acquire_timeout=30s`）已给有界背压；无压测数据调并发闸是臆测，待实测。
- **后台归档 GC reaper** —— #7 的内联 `drop_collection` 才是正确最小范围，reaper 子系统是 v0 镀金。
- **outbox WFQ / per-workspace 租约调度器** —— defer-and-document FIFO；正经调度器正是单节点要避免的复杂度。
- **`fs_udf::block_on().join().unwrap()` 再 panic**（PANIC-4）—— prod 死代码：仅 `current_thread` runtime 臂命中，prod 是多线程 `#[tokio::main]`。无害，跳过。
- **安全响应头（CSP/HSTS/X-Frame）** —— 纯 API 面无浏览器受害者；`/install.sh` 是 `curl|sh` 消费非渲染。nosniff 至多一行。
- **`company_envelope` 的 `to_bytes(body, usize::MAX)`**（DR-7）—— 缓冲的是**服务端自产**的 apps 响应（page size ≤200），非攻击者输入。无放大向量，**明确属过度修复**。
- **数据/控制面 in-code auth extractor** —— 按作者指示由网关 + 网络隔离处理，不计。
- **证伪 #1 reconciler grace 计数器持久化**（DI-5）—— **前提错误**：无 reconciler 定时器（仅按需 `POST /admin/v1/reconcile/{ws}`），prod 配 `grace_passes=0`（首遍即删）。「重启重置计数器」不可能发生。
- **证伪 #2 `quinn-proto`（RUSTSEC-2026-0037）**—— `cargo tree -i quinn-proto -p veda-server` 空；藏在 reqwest 未开的 `http3` feature 后，**未编译**，幻影。
- **证伪 #3 `rsa 0.9.10` Marvin 计时（RUSTSEC-2023-0071）**—— 经 sqlx-mysql 编译，仅用于 MySQL 握手（可信 DB 段），`/v1/*` 不可达；上游无修。接受 + 文档化可信段假设。
