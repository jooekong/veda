## 瓶颈详解

### 🔴 1 · 真实 embedding 是 search/upsert 的吞吐天花板

同一端点 cache 命中 vs 真实 embedding 对照，干净分离出 embedding 的代价：

| hybrid search | 吞吐 | p99 | 错误率 | embedding 层 |
|---|---|---|---|---|
| cache 命中（隔离 Milvus） | 153 QPS | 916ms | 0% | ~0 |
| 真实 embedding | **36 QPS** | **3.94s** | **25.3%** | **1235ms** |

- 单次 query embedding ≈ **1.2s**；50 VU 并发即打爆 airouter，`rate limited (429)` 刷屏（server 日志实锤），错误率 25%。
- **根因**：`veda-pipeline/src/embedding.rs` 有重试 + backoff，但**没有客户端并发上限**。高并发下每个请求各自打 airouter → 429 → 各自 backoff 重试 → 进一步放大压力（雪崩），且重试期间占着请求槽位。
- **建议**：
  - **加客户端并发闸**（Semaphore 限 in-flight embedding 数），把对 airouter 的压力压在它的配额内 —— 防雪崩，**上线前建议**。
  - 429 **快速降级**而非无脑重试放大（尊重 `Retry-After`，超阈值直接返 503 让调用方退避）。
  - 容量侧：airouter 提配额 / 走专用通道（这条不在 veda 代码内）。

### 🔴 2 · Milvus 写入在中并发就严重排队

upsert **cache 命中**轮（已排除 embedding）：60 VU × 50 条/请求 → **2.5 QPS，p99 30s**，归因里 **milvus 层 9–16s**。写入吞吐天花板约 **100–125 条/s**，比读路径低一个数量级。

- **根因**：每次 upsert 走一次 `/v2/vectordb/entities/upsert` REST（`milvus.rs:612`）。并发写下 Milvus 侧（或 REST 网关）排队，具体是 segment/flush 行为还是测试集群规格，**本次未深入到 Milvus 服务端，待定位**。
- ⚠️ **诚实标注**：upsert 两轮参数不等价（隔离 60VU×50 vs 真实 40VU×20），**不可直接对比**；写瓶颈结论只取隔离轮的绝对值（p99 30s、milvus 16s）。饱和排队下三层减法的窗口差分有噪声（出现 store/embed 层数值跳动），但 milvus 层量级足以定性。
- **建议**：先确认线上是读多写少还是写密集。若写密集，需定位 Milvus 写入侧（flush 策略 / segment / 集群规格 / 连接复用）再调优。读多写少则可暂缓。

### 🟡 3 · 每请求 resolve_dataset 查 MySQL，连接池 50 饱和

即使最轻的 query（不走 embedding），e2e 68ms 里 **53ms 在"框架/MySQL"层**（Milvus 仅 15ms），且 150 VU 时连接池 **50/50 打满**。

- **根因**：每个 vectors 请求都 `get_active_dataset_by_name`（`mysql.rs:2561`）查一次 MySQL，**无缓存**。高 QPS 下这一跳 + 连接池争用成了读路径的主要延迟来源。
- **建议**（**最高 ROI，上线前建议**）：dataset 元数据加进程内 **moka 缓存**（key = `workspace_id + dataset_name`，短 TTL，删/改 dataset 时失效）。一次小改即可消掉每请求 MySQL 往返，读吞吐有望大涨。连接池上限也可顺带调大（当前默认 50）。

## 上线前优先级建议

| 优先级 | 动作 | 工作量 | 收益 |
|---|---|---|---|
| **P0** | resolve_dataset 加 moka 缓存 | 小 | 读路径吞吐直接涨，消 MySQL 池压力 |
| **P0** | embedding 客户端并发闸 + 429 降级 | 中 | 防 airouter 雪崩，错误率可控 |
| **P1** | 定位 Milvus 写入排队（若写密集） | 中–大 | 提升写能力 |
| **P2** | MySQL 连接池上限调大 | 极小 | 缓解读路径池争用 |

读路径（query/fulltext/delete）当前已能撑 300+ QPS、p99 < 450ms，对 alpha 上线**读侧无忧**；瓶颈集中在 **embedding 外部依赖**和 **Milvus 写入**两处。
